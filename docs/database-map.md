# ApexTrade V3 - Database Map

## DATABASE MAP

### Table: `signals_history`
- **Purpose**: Stores the output generated by the scanner. Acts as the candidate pool before execution.
- **Fields**:
  - `id` (INTEGER PRIMARY KEY)
  - `symbol` (TEXT)
  - `scanned_at` (TIMESTAMP)
  - `signal_type` (TEXT) - "BUY" or "SELL"
  - `confidence` (INTEGER) - Raw scanner confidence
  - `trade_quality_score` (REAL) - Filtered score post-governance
  - `regime` (TEXT) - Market environment at scan time
  - `entry_price` (REAL), `target_price` (REAL), `stop_loss` (REAL)
  - `status` (TEXT) - "PENDING", "EXECUTED", "REJECTED", "EXPIRED"
- **Relationships**: Parent of `predictions` (conceptually, though hard FK is not enforced, predictions stem from these).
- **Referenced by**: Queries bridging executed trades back to original signals.

### Table: `predictions`
- **Purpose**: Tracks actual trades (paper or live) placed by the autonomous agent or the user.
- **Fields**:
  - `id` (INTEGER PRIMARY KEY)
  - `symbol` (TEXT)
  - `prediction_date` (TIMESTAMP)
  - `prediction_type` (TEXT) - "BUY" or "SELL"
  - `entry_price` (REAL), `target_price` (REAL), `stop_loss` (REAL)
  - `status` (TEXT) - "PENDING", "WIN", "LOSS", "TIMEOUT"
  - `actual_outcome` (REAL) - Final exit price
  - `pnl_pct` (REAL) - Calculated Profit/Loss percentage
  - `trade_quality_score` (REAL)
  - `risk_amount` (REAL) - Capital allocated to the trade
- **Relationships**: Child of `signals_history` (logical correlation).
- **Referenced by**: Performance stats `/api/predictions/stats`, resolver workers.

### Table: `journal_entries`
- **Purpose**: Stores qualitative data, such as trader emotion, system reasoning, and manually logged notes.
- **Fields**:
  - `id` (INTEGER PRIMARY KEY)
  - `symbol` (TEXT)
  - `direction` (TEXT)
  - `entry_price` (REAL)
  - `qty` (INTEGER)
  - `reason` (TEXT)
  - `emotion` (TEXT)
  - `status` (TEXT) - "OPEN", "CLOSED"
  - `created_at` (TIMESTAMP)
- **Relationships**: Standalone / loosely coupled to `predictions`.
- **Referenced by**: `/api/journal` endpoints.

### Table: `data_quality`
- **Purpose**: Logs the ongoing integrity score of the market data and trade resolver logic.
- **Fields**:
  - `id` (INTEGER PRIMARY KEY)
  - `timestamp` (TIMESTAMP)
  - `total_trades` (INTEGER)
  - `valid_trades` (INTEGER)
  - `confidence_score` (REAL) - 0-100 score.
  - `locked` (BOOLEAN) - True if data is deemed untrustworthy.
- **Relationships**: Standalone.
- **Referenced by**: Core backend loop to determine if frontend metrics should be obfuscated.

### Table: `portfolio_snapshots`
- **Purpose**: Records the daily equity curve for the system to evaluate drawdown and daily loss limits.
- **Fields**:
  - `id` (INTEGER PRIMARY KEY)
  - `snapshot_time` (TIMESTAMP)
  - `equity` (REAL)
- **Relationships**: Standalone.
- **Referenced by**: `governance_worker.py` for kill switch logic.

### Table: `key_value_store`
- **Purpose**: A generic storage table for settings, temporary broker sessions, and cached API responses.
- **Fields**:
  - `key` (TEXT PRIMARY KEY)
  - `value` (TEXT)
  - `updated_at` (TIMESTAMP)
- **Relationships**: Standalone.
- **Referenced by**: `angelone_feed.py` for session recovery.

## ENTITY RELATIONSHIPS

**Parent → Child mapping**

- **`signals_history`** → **`predictions`**
  - A signal is generated by the scanner.
  - If approved by the trading agent (or user), a `prediction` is created based on the parameters of the `signals_history` record. The signal's status becomes EXECUTED.

- **`predictions`** → **`journal_entries`** *(Logical)*
  - When the autonomous agent places a prediction, it often auto-generates a corresponding `journal_entry` detailing the logic and risk amount.

- **`portfolio_snapshots`** → *(No Children)*
- **`data_quality`** → *(No Children)*
- **`key_value_store`** → *(No Children)*
